# pi-im

Pi 双通道 IM 插件:飞书 + Telegram,共享主会话,pi-web holder 常驻。

[English](./README.en.md)

仓库:<https://github.com/pananfly/pi-im>

### 前置安装 Pi

如果系统尚未安装 `pi` 命令行工具：

```bash
npm install -g @earendil-works/pi-coding-agent
```

### 插件安装

- **从 npm 安装**:
  ```bash
  pi install npm:@pananfly/pi-im
  ```
- **从本地源码安装**:
  ```bash
  # 在 pi-im 项目目录下执行
  pi install .
  # 或指定目录路径
  pi install /path/to/pi-im
  ```

- 配置:`~/.pi/agent/pi-im/{feishu.json,telegram.json}`
- 预热:`node scripts/pi-web-warmup.mjs --cwd <holder目录> --port 30141`
  (检测到 holder 记录时优先恢复该会话,`--cwd` 仅作兜底)
- Windows 无需 Git Bash,任务计划程序开机跑 pi-web + warmup。

## 通道配置

`feishu.json`:

| 字段 | 说明 |
| --- | --- |
| `appId` / `appSecret` | 飞书自建应用凭据,也可用 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 覆盖 |
| `domain` | `feishu`(默认)或 `lark`(海外) |
| `autoStart` | 默认 `true`,扩展加载即连 WebSocket |
| `allowlist` | 允许使用的用户 id;留空 = **全员拒绝**,`["*"]` 才是显式放开 |
| `progressMode` | `card`(**默认**)或 `text`。新配置走 `/feishu setup` 会直接写成 `card`;随时可在飞书里发 `/feishu card` / `/feishu text` 切换,无需重启,两者形态见下 |

`telegram.json`:`botToken`、`autoStart`、`allowlist`,同上。

白名单只能在 TUI 侧改(`/feishu allow <id>` / `/tg allow <id>`),IM 侧正是它锁住的那条路。

## 进度卡片(`progressMode: "card"`)

飞书卡片 schema 2.0,渲染层对齐 [dsh-im](https://github.com/xmanrui/dsh-im) 的
`stepStreamCard` / `stepPanel` / `processDetailsPanel`,但用 `im.v1.message.patch`
整体替换,不走 cardkit streaming。

- **两个灰底折叠面板**:💭 思考、🛠️ 工具摘要,带边框、圆角和右侧旋转箭头
  (`down-small-ccm_outlined`)。运行中工具面板默认展开、思考默认折叠;整张卡每个
  刷新周期被整体替换,所以用户中途的手动展开状态本来就留不住,能选的只是默认值。
- **结束后收束**:两个面板一起折进一个「📋 过程详情」wrapper,完成态的卡片只占一行。
- **多卡 spill**:单卡预算 24KB(飞书上限约 30KB),超了按 block 边界切成多张,
  除最后一张外都是 sealed 历史卡(灰色 header、标题带「续」),答案不会丢尾巴。
- **表格上限**:一张卡最多 5 个表格(实测第 6 个会整次写入被拒,卡片会卡在旧内容),
  超限时在表格边界切开分配到不同卡片。
- **失败可降级**:patch 失败会记日志并停止后续刷新,结束时改发一条纯文本,
  不会再出现「处理中」永远冻住的静默失败。卡片若**显示**得不顺眼(表格太多、
  面板太挤),可以主动 `/feishu text` 退回纯文本 —— 那是持久化的,重启也保持。

> `schema: "2.0"` 下 markdown 组件的 tag 是 `markdown`;`lark_md` 只作为 1.0 里
> `div.text` 的子字段存在,作为 body 元素会被整卡拒收(`ErrCode 200621`)。

## 消息怎么进到 Pi(先看这三条)

聊天框发任何东西(命令或正文)都要先过三道闸,顺序固定:

1. **白名单 fail-closed**。`allowlist` 为空 = **全员拒绝**,不是全员放行。
   被拒时机器人会回一条消息,里面带**你自己的 user id** 和解锁命令 —— 直接照抄
   到终端执行即可,不用去客户端里翻。
2. **群聊必须 @机器人**。私聊直接回;群里只有 @ 到它的那条才算,@ 别人无效。
3. **去重 + 30 分钟时效**。同一条消息只处理一次;超过 30 分钟的旧消息直接丢弃
   (防止延迟投递的历史消息突然跑一轮)。

## IM 侧命令(聊天框直接发)

> `/help` 在聊天框里只打印一行裸列表,**不带任何解释**。下面的说明是完整参考。

### 查询

| 命令 | 作用 | 注意 |
| --- | --- | --- |
| `/help` | 打印命令列表 | 不含说明,详见本节 |
| `/status` | 版本/渠道、连接、队列、进度展示形态、工作区、会话文件、当前模型、思考档位、上下文占用、运行状态、会话控制是否就绪 | 「会话控制:未就绪」意味着 `/new` `/workspace` `/session` 会失败 |
| `/version` | 版本号 | — |

### 会话与任务

| 命令 | 作用 | 注意 |
| --- | --- | --- |
| `/new` | 新建一个干净的 Pi 会话 | 需要「会话控制」就绪;正在跑任务时会拒绝,先 `/stop` |
| `/stop` | 中止当前正在跑的任务 | — |
| `/steer <文本>` | 追加指令 | 任务运行中 → 并入当前这一轮;不在运行 → 排到下一轮 |
| `/compact` | 压缩会话上下文 | — |
| `/history [N]` | 看最近 N 条历史(默认 3,上限 5) | 每条截断 500 字 |
| `/clear` | — | **当前未接线**,回一句提示,会话不变 |

### 模型与思考

| 命令 | 作用 | 注意 |
| --- | --- | --- |
| `/models` | 列出可用模型(最多展示 30 个),当前模型打 `*` | 序号从这里取 |
| `/model [序号\|ID]` | 不带参数 = 看当前;带参数 = 切换 | 运行中拒绝,先 `/stop`。支持模糊匹配,匹配到多个会要求给完整 ID |
| `/thinking [档位]`(`/reasoning`) | 不带参数 = 看当前 + 可用档位;带参数 = 切换 | 档位表由模型自己的 `thinkingLevelMap` 决定,**不在表里的会被拒绝**,而不是静默降到最低档 |

> `/model` 和 `/thinking` 的选择会被记住:每次 `/new` 之后自动重放回来。IM 侧选的
> 优先级高于终端里临时切的,不会被终端操作覆盖。

### 工作区与会话

| 命令 | 作用 | 注意 |
| --- | --- | --- |
| `/wsl` | 列出工作区(当前目录排第一,带 `(当前)`) | 历史不再只来自 pi-im 自己的记录:每次实时从 `~/.pi` 的 pi-web session index / `sessions/` 目录发现,pi-web 或 CLI 里新建过的目录会直接出现 |
| `/workspace <绝对路径\|序号>`(`/ws`) | 切工作区 | 切的是 **pi 会话的 cwd**,不是 `process.chdir`。目标目录里必须已有 pi 会话,否则只记录不切换,并提示怎么建 |
| `/sessionlist`(`/sessions`) | 列出当前工作区的会话,当前会话打 `*` | 最多展示 20 条 |
| `/session <ID\|序号>` | 绑定到已有会话 | 接受完整 ID、ID 前缀或 `.jsonl` 绝对路径 |

> pi 会话的 cwd 一旦建立就不可改,所以「换工作区」实际是**切到那个目录下的某个
> 会话**,不是改当前进程的目录。这也意味着工作区与会话是绑定的:`/workspace` 会
> 顺带绑定目标目录最新的会话。
>
> **IM 的会话是 pi-im 自己钉住的。** 在 pi-web 里切到别的 workspace 只会打开浏览器
> 那边的会话,不会把 IM 正在执行的任务搬过去:只有 IM 的 `/workspace` `/session`
> `/new`,或你在 TUI 里显式敲 `/feishu` `/tg`,才会迁移 holder(实际执行任务的那个
> 会话)。被钉住的 session/cwd 会写进 `config.json`(`holderSessionId` /
> `holderSessionFile` / `holderCwd`),pi-web 重启后 warmup 优先恢复它——所以浏览器里
> 先打开别的目录也不会把它带跑。同一工作区的别的会话也抢不走它(只认会话文件/会话
> id,不认「目录一样就算同一个」);就算临时顶班的是别的会话,被记录的那个再次出现时
> 会自动把 pin 收回来,但会等当前这一轮答完,免得把正在回答的会话从它自己脚下抽走。
> 你明确选过的(`/workspace` `/session` `/new`、TUI 命令)不会被这个兜底改回去。
>
> `/new` `/workspace` `/session` 真正执行切换要靠 pi-web 侧实现
> `newSession` / `switchSession`(0.11.0 及更早是空实现,只会返回 `cancelled`):
> 用装了这版改动的开发服务(`npm run dev`)或重新构建过的 pi-web。目标会话如果正好
> 在浏览器里开着,切过去的是**同一个**会话——同一份对话两边都能看,不会再开一份拷贝;
> 调用返回时新会话的扩展已经开始重绑,pi-im 不需要再等。
>
> **同一台机器只允许一个进程跑 IM。** TUI 和 pi-web 同时开着时 TUI 优先:持有者记在
> `~/.pi/agent/pi-im/owner.json`(每 10 秒续一次心跳),TUI 一启动就把 IM 接管过来,
> pi-web 退成兜底——它不再长轮询 Telegram、不再连飞书,也不会因为你在浏览器里点开
> 别的会话就把 IM 搬过去。TUI 退出后心跳过期(30 秒)pi-web 才接手,并把 `config.json`
> 里钉住的那个会话恢复回来,IM 不会因此哑掉。两个 TUI 则是先开的那个继续持有。

### `card` 和 `text` 到底差在哪

两者**触发方式、回答内容、模型行为完全相同** —— 区别只在「一条任务跑起来时,你屏幕上长什么样」。
`progressMode` 控制的只有这个。

`text`(默认):

```
收到,处理中…          ← 先发一条占位消息
⏳ bash                ← 原地编辑这一条,不是刷屏
⏳ 正在改 README.md

跑完了:
跑完了:               ← 同一条消息被最终答案整段替换
分析结果如下……(最多 8000 字,超了会被截断)
```

- 一条消息,从头到尾只编辑这一条
- 运行中只有 `⏳` + 工具名 + 最近 500 字文本,没有折叠面板
- 最终答案超过 8000 字会被**截断**(没有分页能力可兜底)

`card`:

```
┌────────────────────────────────────┐
│ ✅ 完成                     1.2s   │
├────────────────────────────────────┤
│ ⚙️ 任务过程                          │  ← 折叠面板,运行中默认展开
│  · bash npm test                    │
│  · edit README.md                   │
├────────────────────────────────────┤
│ 💭 思考                              │  ← 折叠面板,运行中默认折叠
│  先看看现有实现……                     │
├────────────────────────────────────┤
│ 分析结果如下……                       │  ← 答案正文
└────────────────────────────────────┘
```

- 一张飞书卡片(独立消息),每 1.5 秒整体替换一次,不是刷屏
- 工具/思考各有自己的折叠面板,**跑完自动收进一个「📋 过程详情」里**,完成态只占一行
- 单卡预算 24KB,超了自动 spill 成多张卡片(前面的成为历史卡),答案不会丢尾巴
- 没有 8000 字截断:答案以卡片为单位分片,最多约 30KB/卡

怎么选:

| | `text` | `card` |
| --- | --- | --- |
| 运行中信息量 | 少(工具名 + 最近 500 字) | 多(完整工具摘要 + 思考) |
| 长回答 | 8000 字后截断 | 不截断,自动分卡 |
| 过程回顾 | 丢失(被最终答案覆盖) | 保留在「📋 过程详情」 |
| 依赖 | 无 | 渠道需支持发卡+改卡(飞书支持,TG 不支持) |

切换会改 `progressMode`、**写盘**、并**热更新**正在跑的 controller,
**下一轮**对话生效,不需要重启 pi / pi-web。参数大小写不敏感(`/feishu CARD` 等价)。
只认 `card` 和 `text` 两个值,写别的会回用法而不是静默忽略。

**Telegram 上发 `/feishu` 会被直接拒绝** —— TG 网关根本没有卡片能力,假装支持
只会让切换变成一个用户看不见的空操作。

## 工具向你提问(ask_user 等)

IM 发起的任务里,工具弹的对话框会**转发到聊天框**,你回一条消息就能继续 ——
不用回到浏览器面板前面。

```
❓ 选一个继续方向

1) 聊天机器人插件(QQ/微信/TG)
2) 桌面 GUI(类 Codex)
3) 继续打磨 IM 链路

回复序号 1-3,或 /cancel 取消。
```

- **回复方式**:发 `2`(支持全角 `２`、`(2)`),或直接复述选项文字/前缀。
  是/否确认直接回「是」「否」「yes」「no」;文字输入类问题整条消息就是答案。
- **「自己输入」选项被折叠掉了**:ask_user 末尾那个 `✏️ Type custom response...`
  不会列成序号——**想自己写答案就直接发文字**,一步到位,不会再多问你一遍。
- **只接管 IM 发起的回合**。浏览器里发起的任务,提问仍然显示在网页里;
  TUI 模式不接管。被接管的会话是 pi-im 钉住的 holder 会话。
- **ask_user 的复杂面板会降级**:分栏面板在 IM 里读不出也回不了,所以 pi-im 让它
  退回 `select` / `input` 对话框,再逐条转发。单选用序号即可;需要多选或长文本时,
  按提示逐条回答。
- **提问期间命令照常可用**:`/status`、`/model` 等会正常执行,问题保持挂起;
  `/cancel` 取消当前提问,`/stop` 取消提问并中止这一轮。
- **超时与提醒**:工具自己带超时就用它的(例如 ask_user 自带的截止时间);没带则
  10 分钟后自动取消并告诉你。等待超过一半时间时会催你一次,不会静默卡住。
- 回答成功后会回一条 `✅ 已提交: …`,然后任务继续跑。

> 说明:这一层是 pi-im 在 holder 会话的共享 `ctx.ui` 上打的补丁,只影响
> **IM 回合内**的提问;不改 pi-web,也不影响其他会话。

### 答了没反应?开日志再看

「回了序号,机器人一声不响」是最难查的一类:消息可能在飞书网关、白名单、去重、
挂起提问的匹配上任意一处被丢掉。把开关打开,重启跑 pi 的进程,复现一次:

```bash
PI_IM_DEBUG=1 pi          # 或放在启动 pi-web 的环境里
```

不想为了开日志重启?那就放个文件,建了就开始记、删了就立刻停:

```bash
touch ~/.pi/agent/pi-im/debug.on
```

日志写在 `~/.pi/agent/pi-im/debug.log`(超过 1 MB 自动重开),关键几行:

| 日志 | 含义 |
| --- | --- |
| `feishu:reject` | 飞书网关策略挡下了(没 @、非白名单、私聊被关)—— 后面带 `reason` |
| `feishu:unparsed` | 飞书事件里取不到 chat/文本,附原始事件 |
| `inbound` | 消息进了 pi-im,含渠道、chat、发送者、正文 |
| `drop:*` | 被 pi-im 丢掉的原因:`duplicate` / `stale` / `not-allowed` / `no-mention` |
| `ask` / `settle` | 提问挂起、以及最终用哪个值结算 |
| `answer` / `answer:no-pending` | 回复被当成了答案,或没有挂起的提问可匹配 |

`ask` 和 `answer` 行里的短 id 是模块实例标识:同一轮问答出现两个不同 id,说明宿主
重新求值了扩展(切工作区/开新会话),状态因此必须共享 —— 现在就是这么做的。

默认关闭:`PI_IM_DEBUG` 为 `1`/`true`/`yes`,或者 `debug.on` 文件存在,才会写。

## TUI 侧命令(在跑 pi 的终端里敲)

`/feishu`:

| 子命令 | 作用 |
| --- | --- |
| `setup <AppID> <AppSecret>` | 保存凭据并立即启动网关(没配参数时会交互式追问) |
| `start` / `stop` | 启停飞书 WebSocket 长连接 |
| `status` | 凭据是否配置、是否运行中、白名单、自启动开关 |
| `config` | 打印配置目录路径与可用的环境变量覆盖项 |
| `card` \| `text` | 同 IM 侧 `/feishu`,立即写盘 + 热更新 |
| `allow <id>` / `deny <id>` / `allowlist` | 增删查白名单 |
| `logout` | 停连接并清除本地凭据 |

`/tg` 子命令同构:`setup <BotToken>` / `start` / `stop` / `status` / `config` /
`allow` / `deny` / `allowlist` / `logout`。

> **白名单只能在 TUI 侧改。** IM 侧正是它锁住的那条路 —— 如果能从聊天框改白名单,
> 白名单就等于不存在了。被拒时机器人回复里给出的命令就是在终端执行 `/feishu allow <你的id>`。
